# 文档整理：让成果有地方放

第一次正式建项目，只补问缺少的学生姓名。项目名称还没想好就留空，先用学生姓名作根目录；后来确定名称，改成 `学生姓名_项目名称`。下划线是文件名分隔惯例，显示名称仍是“学生姓名＋项目名称”。

在当前工作区内先检查是否已有该学生的项目。新建时采用以下结构；项目没用到的开发部分保持空目录即可：

```text
学生姓名_项目名称/             # 未定项目名时只有学生姓名
├─ 项目说明.md
├─ 01_需求书/
├─ 02_图纸/
│  ├─ 概念图/
│  └─ 流程图/
├─ 03_开发文档/
│  ├─ 开源硬件代码/
│  ├─ 前端代码/
│  └─ 3D建模/
├─ 04_照片素材/
│  ├─ 制作过程/
│  └─ 成品照片/
├─ 05_演示视频和测试视频/
│  ├─ 演示视频/
│  └─ 测试视频/
└─ 06_路演PPT/
```

已有不同结构时先理解对应关系，按需要补齐，不为了整齐重新搬走整个项目。借来的图片与真实制作照片须能区分；可以用简短来源说明，不强迫增加一套复杂分类。

改项目名时，确认原根目录和目标目录都在学生已选工作区内；处理文件名非法字符并告诉学生最终名称。目标已存在时先比较，不覆盖、不擅自合并。如果当前平台正把学生根目录作为工作区而不能重命名，说明需切回外层目录后再改；保持原项目可用，不新建第二套档案充数。

改名后检查相对链接和实际产物是否仍可读。运行中的前端服务、虚拟环境若依赖绝对路径，用相应开发工具恢复运行；不要承诺文件夹改名自动修好所有工具链。

完成时用实际文件树核对目录，报告根目录位置及姓名／项目名；空目录只表示预留位置，不表示素材已经具备。
