# 路演：让学生讲清自己的作品

接上素材检查和当前开题书。先提炼“遇到什么困难 → 现有方法哪里不方便 → 我的目标与方案 → 怎样做出来 → 作品实际怎样 → 还想改什么”。内容须与学生真实做出的成果相符，计划中的功能单独说明。

PPT 与 HTML 演示都是正式交付形式。按学生明确要求选格式；未指定时，根据课堂展示条件和平台实际能力选择合适的一种，简短说明即可，不要求学生先选工具或同时制作两份。

判断优先级：先保证结构、每页重点和逻辑联系，再确定承担解释任务的图片与页面短文字，最后由制作能力完成具体版式、配色和交互。图片的用途是内容要求；裁切、位置和字号等具体做法允许制作 Skill 调整。

## 默认精简结构

约 7 页，可按素材合并，不为凑页数扩写：

| 页 | 讲什么 | 优先素材 |
| --- | --- | --- |
| 1 封面 | 项目名、学生姓名、一句话说明 | 成品图或概念图 |
| 2 问题与现有办法 | 具体使用场景、困难、已有办法仍不便之处 | 已核实调研／真实观察 |
| 3 目标与方案 | 一个核心目标、关键功能、怎样使用 | 开题书与概念图 |
| 4 制作过程 | 实际做过的关键步骤，遇到的问题与修改 | 真实过程照片 |
| 5 作品展示与演示 | 做成了什么，怎样操作，展示主要功能 | 成品图／软件截图、演示视频 |
| 6 总结与改进 | 当前效果、还没解决的困难、下一步 | 学生反馈、实际作品情况 |
| 7 结束 | 一句收束、感谢或邀请交流 | 可与第 6 页合并 |

**不设固定技术原理页。** 目标与方案页可用一整页 [概念原理示意图](gainiantu.md)：产品外形、场景、交互分镜和必要的流程／架构可组合，按需要选择。优先让观众看懂怎样使用；不把需求书整页缩小，也不为了画架构新增一页。只有确有相关测试素材时，在展示后加一页简单测试；没有测试结果就省略，不将开题书中的测试计划写成已验证效果。老师明确指定页数或结构时优先采用，并保留逻辑联系。

## 把每页重点变成看得懂的画面

一页集中说明一个重点。让照片、概念图、交互分镜、截图或图表承担主要信息；页面只留下关键词、关键句、关键结论和必要数字，原因、细节与过渡放进讲解词。不要把需求书段落直接拆成多页，也不要用装饰图标替代有解释作用的图片。图多不是堆小图，一张看得清的大图可以更有效。

| 页面 | 图要让观众理解什么 | 按素材选择的图文起点 |
| --- | --- | --- |
| 封面 | 谁在什么场景使用这个作品 | 场景图或作品主图，项目名与一句介绍 |
| 问题与现有办法 | 困难怎样发生，已有办法留下哪个缺口 | 大场景图配短标注；必要时配少量方案图片与简短对比，突出一个切入点 |
| 目标与方案 | 产品长什么样，怎样操作，如何回应问题 | 大概念图或交互分镜，关键标注与一句核心目标；按需组合流程 |
| 制作过程 | 实际做过什么，怎样修改 | 真实照片／制作截图按过程或修改前后排列，每张配动作短标签 |
| 作品展示与演示 | 最终做成什么，实际怎样运行 | 成品大图、必要细节或软件截图，演示视频与简短操作提示 |
| 可选测试 | 怎样测，观察结果说明什么 | 真实测试现场图、基于实际记录的简洁图表，关键数字和一句有依据的结论 |
| 总结与结束 | 当前完成情况与下一步 | 少量关键词、简短结论；有解释价值再配作品图，不强行加图 |

这些是解释任务和版式起点，不是固定图片数量、占比或唯一排版。已有图片先检查内容再选；缺少场景图或方案说明图时，可调用可用的绘图能力补充，并与真实成果区分。制作、成品和测试证据只能来自真实材料；缺项标待补，不用生成图冒充。不能补图时说明缺口，不悄悄把视觉页改成长篇文字。

## 主动接上平台的制作 Skill

学生提出制作路演后，主动查看当前平台可用的 PPT、演示文稿、HTML 幻灯片或相关制作 Skill／工具。依据它们实际支持的输出格式、项目图片使用、图文排版和预览检查能力，选择适合本次任务的能力，读取说明并实际调用；无需学生再说“请调用 PPT Skill”。优先使用当前已安装、可用的能力，不凭名称声称某个工具最好，也不将本模块变成自动安装任意插件的流程。

本模块负责结构和内容，制作 Skill 负责将它们实现为页面。平台通用模板若与已经确认的页序、核心目标或测试可选规则冲突，应调整模板；不为了模板新增原理页、无依据的测试结果或计划功能。用户明确指定格式时遵守，缺少该格式能力则说明缺口并提出可用替代，不默默改格式。没有专门 Skill 但平台有原生制作能力时可直接使用；两者都没有时才交付内容稿，并说明尚未制作成演示文件。

由 AI 内部整理每页的重点、关键结论、图像用途、真实素材路径／待补项、页面短文字和讲解词，交给制作能力。不让学生手工填表、重复上传已有文件或默认逐页审批。可使用以下交接提示，并填入本次实际信息：

```text
请使用你已读取的演示制作能力，按以下逐页说明制作【本次选定的 PPT 或 HTML 演示】。
先保留页面结构、各页重点和有依据的结论，再围绕指定图片用途安排图文，最后完成具体排版。
图片、截图、分镜或图表承担主要信息，页面只留关键词、关键句、关键结论；详细解释放进讲解词。
每页说明：【本页重点；关键结论；图片用途；可用素材路径或待补项；页面短文字；讲解词】。
请实际使用提供的素材，缺素材时按指定边界补充说明图或标待补，不虚构过程、成品或测试证据。
按实际内容调整版式，不让通用模板改变已经确认的项目逻辑，不以大段文字填满缺图的位置。
生成后预览并检查各页，修正文字堆叠、图片太小、裁切错误、标注错误和内容不一致，再交付文件与逐页讲解词。
```

## 按选定格式完成并检查

本模块不自带固定渲染器或模板脚本。PPT 输出可编辑 `.pptx`，文字为文本框，图片可替换，不能用整页截图冒充可编辑稿。HTML 输出能在浏览器展示的演示文件，提供清楚的分页／分屏阅读顺序和适合课堂的切换方式，保留可修改源文件；普通长篇报告网页不能直接当作路演完成。图片与视频采用实际可用的嵌入或相对依赖，交付时说明需要一并保留哪些文件；只有验证过独立打开，才能称为单文件或离线可用。

有预览能力就实际查看页面，检查打开、页序、文字溢出、图片大小／裁切、标注、图文关系及视频播放或链接条件；HTML 还检查展示导航。先核对结构和内容，再核对图是否解释了本页重点，最后检查版式。仍以长段文字为主时回到本页重点和视觉安排修改，不以文件生成成功结束。没有预览能力时如实标明未验证的部分，不声称视觉验收通过。视频封面图不等于视频已经嵌入。

同时交付一份**简短逐页讲解词**，默认每页两三句，学生能理解、能讲出来。对应最终实际页面，不写长论文式旁白，不虚构“我采访了”“我们测试证明”等经历。可以使用“我发现……”“所以我想……”“现在做到的是……”“接下来想改……”这类自然表达，但要有事实依据。

PPT 或 HTML 演示、必要依赖和讲解词保存在 `06_路演PPT/`，沿用现有目录名，不因格式改变重建项目；原图和视频继续保留在素材目录。若素材暂缺且学生要求先做草稿，清楚标出待补项；交付前核对讲解词、页面、实际作品是否一致。
