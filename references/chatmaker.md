# ChatMaker：接上需求，用原生能力制作原型

ChatMaker 独立官方仓库：**https://github.com/Amasun93/ChatMaker**。

先查当前平台是否已安装可用的 ChatMaker。已可用就直接读取它的入口；未安装时帮学生从上述仓库按仓库当前安装说明和宿主实际支持的方式安装，再检查入口及引用资源可读。安装的是完整 ChatMaker 能力包，不仅复制孤立的 `SKILL.md`。如果宿主不能自动安装，明确阻碍和需要老师完成的那一步，不宣称成功。

仓库的 `skills/chatmaker/SKILL.md` 是入口；原生包可能把专业模块放入 `internal_skills/`。源码与安装包布局不同时，使用仓库提供的构建／安装方式或按其清单组装并验证全部引用，不猜路径。不要让学生分别安装 ChatDuino、ChatWeb、ChatCAD，不将它们重新实现到本 Skill。

2026-11-12 核对的官方源码提供 `scripts/build_chatmaker_skill_bundle.py`。在克隆的 ChatMaker 仓库内可用 `python scripts/build_chatmaker_skill_bundle.py --output <全新暂存目录>` 组装完整包；核对入口和三个内部模块后，再安装到宿主的 `chatmaker` 技能目录。已有安装先比较，不能用构建脚本直接覆盖。没有 Python 时，可依据原生脚本的文件映射复制完整目录：`skills/chatmaker/` 内容作为包根，另外三个 `skills/chatduino/`、`skills/chatweb/`、`skills/chatcad/` 分别放入包内 `internal_skills/` 的同名目录。保留各自参考资源，检查相对引用；未来仓库布局变化时以当时原文为准。这只是安装文件，不代表已经安装编译或烧录环境。

接续时给 ChatMaker 这些已有上下文：

- 当前学生项目根目录与最新开题书的位置；能读取就直接提取核心目标、功能、测试计划。
- 概念图的位置以及学生刚补充的新想法。
- 对应开发产物应保存到哪里；真实已有代码或原型优先复用。

随后遵循 **ChatMaker 原生能力**：确认这次到底要开发什么、有没有新想法，学生确认后先做基础原型，再通过反馈迭代。不要在外面再加一轮强制需求表、复杂交接文件或多重审批。学生在当前请求里已明确确认的内容无需重复问同一个问题；硬件型号等实际影响实现的缺口仍由原生模块判断。

硬件程序放 `03_开发文档/开源硬件代码/`，网页源文件放 `03_开发文档/前端代码/`，建模源文件及真实导出放 `03_开发文档/3D建模/`。保留原生所需的项目内部结构和运行环境，不为归档把一个可运行项目拆散。

交付状态以实际证据为准：生成了代码、成功运行、编译通过、烧录成功、实物验证分别说明。只有 OpenSCAD 代码时就保存代码，不登记不存在的 STL；模型图不是实物照片。纯代码生成不强制安装全套工具链，真正需要编译、烧录或渲染时按原生指引处理。
